# Rule catalogue

Generated by `python -m sproc_to_lakehouse rules` from the analyzer's code. Each rule classifies a T-SQL construct as `auto` (converts with the same meaning), `auto_with_note` (converts; a small semantic difference is worth checking) or `needs_review` (a person must decide). Some rules use more than one severity depending on what they find; reports always say which and why. Rules marked *needs DDL* only run when table definitions are loaded.

## Fixes applied by the generator

Some constructs only count as automatic because the generator corrects what a plain SQL translation (sqlglot) gets wrong. A test fails if the analyzer promises a fix the generator does not implement.

| Fix | What it does |
|---|---|
| bit_to_boolean | BIT columns are BOOLEAN on Databricks: 0/1 comparisons become FALSE/TRUE and values written into them are cast to BOOLEAN (needs DDL). |
| compact_date_literal | 'yyyymmdd' strings compared with dates become DATE literals; Spark cannot cast them implicitly (needs DDL). |
| iso_week_extract | EXTRACT(WEEKISO ...) becomes EXTRACT(WEEK ...), the Databricks ISO 8601 field. |
| plus_to_concat | String '+' becomes CONCAT; sqlglot leaves '+', which Databricks treats as numeric addition. |
| transient_table_to_cte | Temp tables / table variables populated without later mutation become CTEs (or intermediate models when read more than once). |
| try_convert_safe_parse | TRY_CONVERT with a style becomes CAST(TRY_TO_TIMESTAMP(...)); sqlglot emits TO_DATE/TO_TIMESTAMP, which raise on bad input. |
| update_from_to_merge | UPDATE/DELETE ... FROM ... JOIN becomes MERGE INTO, because Delta UPDATE/DELETE has no FROM clause. |
